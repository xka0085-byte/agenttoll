Agent 怎么工作、怎么发现工具

从底层逻辑推导 AgentToll 的「被发现」方案 —— 一切以实测数据为准，不以行业 hype 为准

一、Agent 的底层工作循环（ReAct）

所有工具型 agent（Claude Code、Cursor、我们自己在用的这套）本质上是同一个循环：

推理 → 选工具 → 调用 → 读结果 → 再推理……直到任务完成 模型不「上网浏览」，它只能看到两类东西：①上下文里已有的信息（系统提示、对话、工具清单）和 ②工具调用返回的结果。工具调用是结构化的 function calling：模型输出 JSON 参数，运行时执行，结果回填上下文，循环继续。

推论 1：工具的「定义文本」就是 agent 的全部视野。Neo4j 的工程结论：模糊的名称、单薄的描述、重叠的功能会直接导致模型选错工具。换句话说——我们对工具描述文本的措辞，就是我们的 SEO。

二、工具从哪来：三层发现机制

层机制agent 怎么命中你我们要做什么
① 预配置层用户手动把 MCP server 写进配置（如 mcp.json），启动时 tools/list 拉取全部工具定义被用户「点名安装」——npm 包名、文档教程、目录页是入口npm 发 @agenttoll/receipts-mcp，README 写清场景词
② 注册表层官方 MCP Registry（Anthropic 2025-12 捐给 AAIF 基金会，REST API：GET /v0.1/servers?search=x402 receipt）。Kong 等已实现企业级注册表。另外部分 agent 有内置的延迟工具检索（按需模糊搜索工具库）agent 运行时按任务关键词查询注册表，机械匹配 name + description + 元数据注册表提交 + 工具描述文本按检索词优化（这一条之前被我们低估）
③ 网络检索层agent 任务缺口时自己上网搜/抓：搜索引擎、x402scan 等目录、以及抓取 /.well-known/agent-card.json、SKILL.md、Schema.org 结构化数据网页内容 + 结构化标记 + 目录条目见第四节优先级

三、实测案例（不是 hype，是上线了的东西）

案例 1：DirectBooker（酒店业）—— MCP 被大企业当官网级别的入口 一个把酒店直连房价喂给 ChatGPT/Claude 的 MCP server，全球十大酒店集团中的五家（含 BWH、丽笙）签约接入，覆盖 2.5 亿+ 会员——它们用它绕开 OTA。证明：MCP 端点已经是企业愿意签合同的正式销售渠道。
案例 2：PayanAgent —— SKILL.md 让 agent 零集成可用 curl payanagent.com/SKILL.md 输出喂给任何 LLM agent，立即具备发现/购买/开回执能力。它不做人类营销，靠 SKILL.md + npm MCP + 目录收录吃 agent 流量。
案例 3：Google UCP —— well-known 模式 6 个月进入生产 Google 2026-01-11 发布 UCP（与 Shopify/Walmart/Target 共同开发），用 /.well-known/ucp 模式 + 强类型 schema，已支撑 Google AI Mode 的结账。证明 /.well-known/ 机器发现模式已是生产级基础设施。
案例 4（反面）：llms.txt 被高估了 bluerails 基于 30 万域名（SE Ranking）+ 服务器日志的实测：主流 LLM 爬虫几乎不抓 llms.txt（采用率 ~10%，无可测量的引用提升）。但 IDE 型 agent（Cursor/Cline）和 MCP 集成确实会消费它。结论：值得发（30 分钟成本），但别指望它带来流量。
案例 5（我们自己）：本会话就是活的证据 我这个 agent 的工具分两层：系统提示里预配置的工具 + 运行时按需检索的延迟工具库（模糊匹配工具名和描述才加载）。我找 x402 服务时走的是 WebSearch + x402scan 抓取——正是第③层通道。我们自己的行为就验证了这套发现模型。

四、修正后的优先级（重要：和之前方案有两处不同）

修正 1：llms.txt 降级 —— 之前排在发现通道前列，实测数据显示主流爬虫不抓它。保留（成本≈0），但不指望它。
修正 2：Schema.org JSON-LD 是被我们漏掉的最高杠杆项 —— bluerails 结论：结构化数据是 2026 年 agent 自然发现中杠杆率最高的单一信号，agent 读 schema 标记远比读页面布局可靠。我们要给报价页和服务文档加 Product/Service + Offer 的 JSON-LD。

五、设计推论：文案即架构

三层发现机制的共同汇点是文本：MCP 工具描述、注册表元数据、schema 标记、SKILL.md。所以有一个统一的写作规范：

  1. 名称含检索词：工具名里要有 x402 / receipt / escrow / verification / solana
  2. 描述回答三个问题：干什么（issue/verify delivery receipts）、什么时候用（after x402 settlement / before accepting delivery）、输入输出是什么
  3. 数字前置：AEO 内容规范——每段第一句是可直接抽取的答案（agent 合成回复时优先抽取）
  4. 时新性：agent 的信任信号第一位是「最近更新过」——spec 版本号、页面日期要持续滚动
